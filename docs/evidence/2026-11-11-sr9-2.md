# 2026-11-11 SR9-2 destination probes

**Question:** for the cells SR9-1 left on a generic page (SportPlus, Premier
Kladionica, WWIN live, MaxBet, Betole live), does the book offer a per-fixture
URL — or a slip route — that works without a login?

**Browsers:** plain headless Chromium 1440×900 / 1600×1000 (`--no-sandbox`,
no request blocking). The MaxBet checks used the project's own API headers; the
route probes used a fresh context with the Bosnian locale.
**Safety:** no login, no account endpoint, no stake entered, nothing submitted.

## MaxBet — ticket filled, both modes (shipped)

The adapter's own list response already carries everything the slip needs:
`odds[].outcomes[].id` is the per-row id (`outcomeId` is the type id, `1001` for
"1", and fills nothing). The URL is
`https://www.maxbet.ba/ba/sportsbook/match/{event_id}?outcome={outcome_id}`.

Screenshots: `docs/evidence/2026-11-11-sr9-2/maxbet-ticket-1027619.png` and
`maxbet-live-ticket-1032215.png`. The live ids come from the same
`/rest/v2/matches?status=Live` request the adapter already makes.

`?outcome=` with a *missing* or non-row id puts nothing on the slip; the
destination therefore falls back to the confirmed match page (`ticket
parameters missing`) instead of showing an empty ticket. The dated fixtures were
re-captured the same day (`scripts/capture_market_fixtures.py --books maxbet`)
so `outcomes[].id` is part of the frozen shape and the parser contract; the
"unpriced control" total moved from 4.5 to 6.5 because the registry now prices
4.5 and 5.5.

## SportPlus — no per-event URL (confirmed again)

- `/prematch/betting` and `/live/betting` render rows in a client-side app; the
  only anchors on either page are the navigation links. No `/match/<id>`,
  `?event=` or hash route exists in the served app (`prematch-desktop` bundle:
  no router, no `navigate`, no URL read for the fixture).
- A match row has no link and clicking it adds a pick to the slip instead of
  navigating; the slip itself is built client-side
  (`{sportId, matchId, matchDate, market, odd}`) and read from
  `localStorage["cn-prematch.ticket"]`.
- The site's own ticket controls are "Obični/Sistemski" and a slip reset; there
  is no share/booking-code URL that creates a ticket.

So the honest destination stays the competition page plus the copyable
`localStorage` prefill script (prematch only; the live offer shape is not
confirmed). A bookmarklet would not improve it: a `javascript:` link clicked in
the dashboard runs in the dashboard's origin, not SportPlus's.

## Premier Kladionica — no per-event URL (confirmed again)

- `/ponuda/` (prematch) and `/live` are one Next.js shell around the site's TTX
  client. Neither page renders any anchor; the offer is drawn from a remote
  module.
- A live match row carries `data-who="3.2.3481.15178.1.2.10.11449.4594875"`
  (sport/league/event ids) but has no link: clicking the row or a price leaves
  the URL unchanged at `/live`.
- The URL does not open a fixture: `/live?who=<data-who>` and
  `/live#/who=<data-who>` both keep the generic live list (no fixture heading).
- The only token route the site publishes is
  `/remote-module/provjera-listica-po-uplati/?token=…`, which looks up a ticket
  by its payment token — it creates nothing and is not a destination.

## WWIN live — match page, operator-confirmed

`https://wwin.ba/kladjenje-uzivo/#/match/{event_id}` opened the in-play fixture
in headless Chromium on 2026-11-11 (SR9-1). The operator then opened it with a
live id from the same day's scan (`4732588`, Z.Podbrezova – Z.Moravce) in a
normal browser and reported that it opens the fixture, so the route is promoted
to a confirmed match page. The OpenChamber panel still renders WWIN as an empty
shell, so the operator's browser is the reference, as for prematch.

## Betole live — no live leg to link

The adapter prices no Betole live leg: its desk feed exposes rest-of-match
markets without a score field, so a live 1X2 cannot be told apart from a
full-time one (`docs/DESTINATIONS.md`, "Honest limits"). Nothing to upgrade
until SR8-1/SR8-3 change the live offer; the copy-only fallback stays.

## Mozzartbet live (lead, not one of the nine cells)

The live route needs the live-feed id, which the adapter does not parse; its
live rows come from the prematch feed. That is SR8-1 work, and the destination
stays on `/sr/uzivo` until the adapter carries the live id.
