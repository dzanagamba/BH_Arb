## Findings (each became a roadmap row)

1. **Live Mozzartbet and Betole return zero matches.** Both answer (6 and 5
   requests, 0.74 MB and 2.1 MB of body) but parse to nothing, and the same two
   books were `empty` in live in the 2026-11-08 baseline
   (`2026-11-08-scan-cost-baseline.md`). Twice in a row with bytes on the wire is
   not "no live events"; it needs a capture. → **SR8-1**.
2. **Structural-drift alarms are noisy and partly stale.** The run logged 173
   `[mozzartbet] structural drift at offer` lines (one per offer, all
   `removed=match.oddsGroup[].odds[].value:number`, i.e. fully suspended offers,
   which SR4-10 accepts), plus drift on `wwin` prematch-events (events with no
   `bets`), `mbet`/`maxbet` list pages whose whole item shape is absent (empty
   pages) and `admiralbet` (`sBV*`/`tOT*` → `sbv*`/`tot*`, a real casing change
   that `scrapers/common.py` already reads both ways, so prices are unaffected).
   → **SR8-2**.
3. **Mapping coverage is far below its floor.** Prematch 45,678 / 454,293 rows
   mapped, live 718 / 89,919, against `MAPPING_COVERAGE_FLOOR` 0.95. The
   denominator is dominated by unregistered full-offer markets (for example
   `betole:10`…`betole:18` at 940 rows each, after SR7-1), so the warning fires
   every scan and no longer separates a regression from the known long tail.
   → **SR8-3**.
4. Expected, not defects: `mbet` and `sportplus` prematch were feed-integrity
   `quarantined` with reason `recovering` (one healthy scan after an older
   unhealthy one — the hysteresis working); `betole` and `mozzartbet` live were
   quarantined for being empty; 22 frozen `maxbet` rows were refused; two
   ~23 % "surebets" (`torque vs racing club`) were rejected as data errors and
   five outlier-leg surebets were dropped. `mdshop` and `admiralbet` report
   identical metrics (same feed; skin detection counts them as one source).

## How it was run

A driver outside the repo (`/tmp/bhscan/scan_both.py`, not committed):

```python
from server import api
from server.app import _restore_state
import record_scan          # scripts/ on sys.path
_restore_state()            # without this, run_scan rewrites scan_cost.json from empty globals
for mode in ("prematch", "live"):
    report = await record_scan.run(mode)
```

`cache/scan_cost.json` history went from 1 to 3 entries (the 2026-11-08
prematch baseline was kept). `git status` was clean afterwards; only `cache/`
runtime state changed. SR8-4 folds the restore into `scripts/record_scan.py`.
